## New diagnostic v0.3 — bounded recorder transcript source, EOS/reconnect SESSION evidence only

- **Implemented:** `diagnostics/C545D-WeeklyObserver.ps1` **v0.3.0** (additive ZIP schema v1) scans only existing `Recording_YYYYMMDD_HHMMSS_PID.txt` `RecordGUIWorker.ps1` transcripts from the private log directory; scans are read-only, file size <=8MiB, max 100 candidate files / 80 selected sessions / 100000 lines per file, with invalid/oversize/reparse/partial sources marked explicitly. Does not inspect command line, private recorder variables, RTSP URLs, passwords, videos or live MP4. No recorder code change.
- **Safe output:** new `recorder_sessions.csv` has only source **file last-write UTC** (selection timestamp, **not** actual EOS time), artificial per-report session index, `source_status` enum, integer launches, GST return/nonzero-exit, exit without authorized GUI stop marker, source reconnect policy, source-reported authorized EOS and literal `session_only` time resolution. No PID, user file name, raw transcript text, unapproved network or path. Existing `recording_events.csv` retains finalized rename/counts only; EOS display not interpreted as proof of MP4 integrity, AAC or two cameras.
- **Strict source success rule:** `Record.ps1` must produce in a single **completed** transcript the exact ordered `GStreamer returned; exitCode=0; stopMarker=True; consoleCtrlCEvents=N` + `Recorder exit policy: stop` + `Recording stopped by GUI; GStreamer EOS completed.` before one `Windows PowerShell transcript end`. An isolated success string **without** a corresponding authorized exit+policy is explicitly rejected; unclosed or truncated logs count as **incomplete/unknown** even when the success string exists. An absent complete log is NOT evidence of zero recorder errors. A reconnect policy means decision to retry, not confirmed RTSP reconnect.
- **Limitations:** PowerShell 5.1 `Start-Transcript` is not a timestamped event stream by default; Do NOT correlate exact minute of an EOS/reconnect with minute-resolution PrivateUsage or assert `source_last_write_utc` is the event time. A long-running transcript may span reporting intervals. `recorder_session_event_source_status` captures `not_found/no_sessions_in_window/partial_or_active` etc; actual `eos_confirmation=recorder_log_reported_only_not_mp4_proven`, `video_stream_count/aac_audio_integrity/mp4_duration=not_collected`. The fact that `Stop-Transcript` is used by the worker does not prove every error path will have a footer.
- **Isolated Windows tests:** [#45237910384 SUCCESS](https://github.com/taku077/c545d-recorder/actions/runs/45237910384) validates exact source pair, bogus EOS rejection, incomplete-source rejection, sanitation and no field coercion of private secrets; [#45238100524 SUCCESS](https://github.com/taku077/c545d-recorder/actions/runs/45238100524) confirms missing/partial source status. ## Policy for the next loop

Approved release -> user records while detached lightweight monitor runs -> one-off ZIP at 72h, every seven days thereafter -> chat examines validated samples, missing classifications and recorder health -> AI continues isolated CI/root-cause work without awaiting ZIP -> versioned standalone diagnostic update and independently verified recorder correction -> next safe release as evidence warrants. Software release interval is **not** fixed to one week. Diagnostic-only upgrades must not stop recorder or alter the approved GStreamer runtime. No automatic external upload or public private data. Maintain prior working package and a reversible stop/EOS/offline-change process.
