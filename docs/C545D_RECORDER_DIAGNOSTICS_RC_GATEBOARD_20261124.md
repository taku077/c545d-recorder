## New diagnostic v0.2 — no-invasive closed-segment signal from existing renamer log

- New `diagnostics/C545D-WeeklyObserver.ps1` **0.2.0** adds a strictly allowlisted **read-only** scan of the already-existing `%LOCALAPPDATA%\\C545D_GStreamer\\Logs\\Filename_Rename.log`. `SegmentNamer.ps1`/the GStreamer recorder pipeline/worker/MP4 files are **unchanged**. No enumeration of recording folder, no opening live MP4 and no ffprobe triggered by weekly observer. The source renamer emits `Renamed (closed)` only **after** its exclusive-open check, optional ffprobe and successful intra-folder `Move-Item` (verified in source); the event is **NOT** proof of dual video tracks, AAC, timestamp integrity, MP4 decode or EOS. Neither 1-hour exact duration nor 24/7 integrity is inferred from count alone.
- ZIP v0.2 contains `recording_events.csv` in addition to existing v0.1 numeric CSV/manifest/summary; event rows are ONLY ISO UTC timestamp + allowlisted enum + integer count. Types: `MP4_RENAME_AFTER_CLOSED`, `MP4_RENAME_DEFERRED`, `MP4_WATCHER_LOST_EVENTS`, `MP4_WATCHER_SHUTDOWN_TIMEOUT`, `MP4_WATCHER_ERROR`. Any filename, RTSP/credentials, raw exception line, native log body or output folder path is discarded. Raw log size capped at 8MiB, 100000 lines, 20000 exported events. `namer_event_source_status=not_found/source_too_large/source_reparse_rejected/scan_limit/event_limit/source_unreadable/complete`; absent, invalid, oversize or truncated logs are NOT treated as zero-error evidence.
- Manifest retains schema `1`, additive fields and upgraded diagnostics version `0.2.0`. Explicit `video_stream_count/aac_audio_integrity/eos_confirmation/mp4_duration=not_collected`. This is a step toward quality metrics, not full validation.

## Policy for the next loop

Approved release -> user records while detached lightweight monitor runs -> one-off ZIP at 72h, every seven days thereafter -> chat examines validated samples, missing classifications and recorder health -> AI continues isolated CI/root-cause work without awaiting ZIP -> versioned standalone diagnostic update and independently verified recorder correction -> next safe release as evidence warrants. Software release interval is **not** fixed to one week. Diagnostic-only upgrades must not stop recorder or alter the approved GStreamer runtime. No automatic external upload or public private data. Maintain prior working package and a reversible stop/EOS/offline-change process.
