## Before a user-approved trial

- Record exact previous working package and candidate identities, retain both complete folders, and check expected SHA-256 of the candidate. Never overwrite the running folder, shared configuration, GStreamer SDK, or diagnostic history. If package cannot be identified, do not proceed.
- Check candidate default settings and available disk capacity. Keep the previous app usable under the same Windows user (DPAPI). Never copy credentials to a public repo or report.
- On explicit authorization only: use old GUI normal Stop, wait for final MP4 and worker/watcher exit; exit old GUI; start candidate from separate folder. Verify configuration and start recording normally. Do not start a second recorder, replace loaded DLLs, or use force-stop as the ordinary path.
- Run one integrated initial real-camera acceptance: confirm wide-left/tele-right, audio and synchronization, first actual hourly file close, profile and playback, continued resource sampling, and normal EOS on the planned stop. Use the same low-frequency observer for ongoing monitoring; first report 72h, then seven days. A single planned acceptance is not proof of 24/365 stability.
- Rollback if unsafe: normal Stop and confirm final MP4, close candidate and its watcher; close only the candidate observer if necessary, not the recorder from the observer; start old version from preserved folder and verify recording. No DLL swaps. If normal stop fails, do not escalate automatically; preserve evidence and treat as a separate safety incident.
